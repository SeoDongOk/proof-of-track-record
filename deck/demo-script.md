# 데모 영상 스크립트 (3분 이내)

폼의 데모 영상은 **선택**이지만 심사 4단계 "데모 접근성"에 직접 작용한다.
아래 그대로 읽고 `demo-run.sh` 를 돌리면 2분 30초 안에 끝난다.

## 준비

```bash
cd ~/project_vs/proof-of-track-record
npm run build          # 미리 해둘 것. 영상에 컴파일 40초를 담지 않는다
```

터미널 폰트를 키우고(16pt+) 창을 넓게. 화면 녹화는 macOS `Cmd+Shift+5`.

## 구성

| 구간 | 시간 | 말할 것 |
|---|---|---|
| 1. 문제 | 0:00–0:40 | 백테스트 이야기 |
| 2. 해법 | 0:40–1:00 | 사전 커밋 + ZK |
| 3. 데모 A | 1:00–1:45 | `npm run nav` |
| 4. 데모 B | 1:45–2:15 | `npm run verify` |
| 5. 온체인 | 2:15–2:40 | Preview 블록 번호 |

---

## 1. 문제 (0:00–0:40)

> 트랙 레코드를 볼 때 보통 "조작했나"를 묻습니다.
> 그런데 더 위험한 건 숫자가 전부 진짜인데도 거짓말이 되는 경우입니다.
>
> "1년 동안 전략 10개를 돌렸다, 이게 그중 제일 잘 된 거다" — 모든 거래가 실제고
> 수익률도 정확하지만, 다음에 무슨 일이 일어날지는 알려주지 않습니다.
>
> 저에게 실제로 있었던 일입니다. S&P 500 백테스트가 연 23.63% 로 나왔는데
> 생존 편향을 제거하니 14.48% 로 주저앉았고, 초과수익 p 값은 0.566 이었습니다.
> **조작한 건 하나도 없었습니다.** 파이프라인이 그저 다시 돌릴 수 있었을 뿐이고,
> 그 과정은 흔적을 남기지 않습니다.

## 2. 해법 (0:40–1:00)

> 그래서 결과를 알기 **전에** 전략을 온체인에 커밋하고, 나중에 성과가
> **그** 커밋된 전략에서 나왔음을 영지식으로 증명합니다.
>
> 사전 커밋만이면 해시로 충분한데, 트레이더는 전략을 공개할 수 없습니다.
> 공개하면 알파가 죽으니까요. 그래서 ZK 가 필요합니다.

## 3. 데모 A — 손실을 빼고 계산할 수 없다 (1:00–1:45)

```bash
npm run nav
```

> 회로 5 입니다. 실제 거래는 5승 3패, 합계 마이너스 400bp 입니다.
>
> 수익 난 5건만 골라서 "플러스 950bp" 라고 주장하면 — **거부**됩니다.
> 실제 결과인 "마이너스 400bp 이상" 은 통과합니다.
> 1bp 만 부풀려도 거부되고, 시작 잔고를 사후에 절반으로 낮춰도 거부됩니다.
>
> 거래 로그만으로는 손실을 빼고 커밋할 수 있습니다. 그런데 NAV 는 잔고 자체라,
> 거래를 빼도 숫자가 바뀌지 않습니다.

## 4. 데모 B — 계정 없이 검증 (1:45–2:15)

```bash
npm run verify
```

> 이건 저장소에 들어 있는 **실제 zkTLS 증언**입니다.
> Primus 공증인이 바이낸스 API 를 TLS 세션으로 직접 읽은 것이고,
> 서명이 붙어 있습니다.
>
> 검증은 순수 ECDSA 복원이라 **네트워크도 계정도 필요 없습니다.**
> 그리고 값을 한 글자만 바꾼 사본은 거부됩니다 — 매 실행마다 확인합니다.

## 5. 온체인 (2:15–2:40)

```bash
cat deck/onchain.txt
```

> Midnight Preview 공개 테스트넷에 올라가 있습니다.
> 컨트랙트 배포 두 건과 회로 호출 다섯 건입니다.
> 증언된 값은 실제 바이낸스 선물 계좌의 잔고이고,
> **원장에는 커밋만 있고 NAV 값은 체인에 가지 않습니다.**
>
> 누구나 인디서로 확인할 수 있습니다.
